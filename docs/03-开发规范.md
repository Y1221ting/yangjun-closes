# 03 - 开发规范

> 个人衣柜 · 代码风格、命名、错误处理与文件模板
> 文档版本：v1.0　|　编写日期：2026-11-18

---

## 一、总原则

1. **先跑通，再好看**：每个阶段结束时程序必须能运行，不允许留下半成品状态
2. **一次只做一个功能点**：做完、验证、记录，再开始下一个
3. **数据永远比界面重要**：任何导致数据丢失的写法都不接受
4. **注释写给三个月后的自己**：中文注释说明「为什么」，代码本身说明「做什么」
5. **不引入不必要的依赖**：每多一个库，打包就多一个坑

## 二、Python 规范

### 2.1 基本

| 项目 | 规定 |
|------|------|
| 标准 | PEP 8 |
| 行宽 | 100 字符 |
| 缩进 | 4 空格 |
| 编码 | UTF-8，文件头不写 `# -*- coding -*-` |
| 引号 | 统一双引号 `"`（字符串内容含双引号时可用单引号） |
| 类型注解 | 所有函数必须写参数与返回类型 |
| 命名 | 模块/函数/变量 `snake_case`；类 `PascalCase`；常量 `UPPER_CASE` |

### 2.2 模块文件头

每个 Python 文件开头必须有模块说明：

```python
"""衣服业务逻辑。

负责衣服的增删改查、图片关联、筛选条件组装。
数据库操作统一经由 db.py，不直接 import sqlite3。
"""
```

### 2.3 函数 docstring

```python
def list_garments(filters: dict) -> list[dict]:
    """按筛选条件查询衣服列表。

    Args:
        filters: 可包含 category / color / season / scene / q 五个键。

    Returns:
        衣服字典列表，按创建时间倒序。

    Raises:
        ValueError: 当 category 不在允许范围内时。
    """
```

### 2.4 禁止事项

- 禁止裸 `except:`，必须写明捕获的异常类型
- 禁止在循环里反复 `connect()` 数据库（每次查询开一次连接即可）
- 禁止在 Python 层拼接 SQL 字符串，一律用 `?` 占位符
- 禁止把绝对路径硬编码，统一从 `config.py` 取
- 禁止在 `api/` 层写业务逻辑，业务逻辑放 `services/`

## 三、数据库规范

### 3.1 连接

```python
def get_conn() -> sqlite3.Connection:
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    return conn
```

### 3.2 操作模板

所有写操作必须包在事务里，并且有异常处理：

```python
def create_garment(data: dict) -> dict:
    """新建一件衣服。"""
    now = now_str()
    conn = get_conn()
    try:
        with conn:                      # 自动提交 / 回滚
            cur = conn.execute(
                "INSERT INTO garments (name, category, color, seasons, occasions, "
                "created_at, updated_at) VALUES (?, ?, ?, ?, ?, ?, ?)",
                (data["name"], data["category"], data.get("color"),
                 json.dumps(data.get("seasons", []), ensure_ascii=False),
                 json.dumps(data.get("occasions", []), ensure_ascii=False),
                 now, now),
            )
            garment_id = cur.lastrowid
        return get_garment(garment_id)
    except sqlite3.Error as exc:
        logger.exception("创建衣服失败")
        raise ServiceError("保存衣服失败，请重试") from exc
    finally:
        conn.close()
```

### 3.3 迁移

- 表结构变化时，在 `db.py` 里写 `_migrate_v{n}()`，用 `PRAGMA user_version` 记录版本
- 迁移必须幂等：重复执行不报错、不重复加列

## 四、前端规范

### 4.1 结构

- 纯 HTML / CSS / JavaScript，**不使用框架、不使用构建工具**
- 每个 JS 文件一个 IIFE，挂到全局 `App` 命名空间下
- 页面切换由 `router.js` 控制，所有页面都在 `index.html` 里以 `<section>` 存在，
  切换时只改 `hidden` 属性和 `data-page`

### 4.2 JS 模板

```js
/* 衣柜页：网格渲染、筛选、搜索。 */
(function (App) {
  'use strict';

  const state = { items: [], filters: {} };

  async function load() {
    const params = new URLSearchParams(state.filters);
    const res = await App.api.get('/api/garments?' + params.toString());
    state.items = res.data;
    render();
  }

  function render() {
    // ...
  }

  App.wardrobe = { init, load, render };
})(window.App = window.App || {});
```

### 4.3 命名

| 类型 | 规范 | 示例 |
|------|------|------|
| CSS 类 | 小写 + 连字符，`块-元素-修饰` | `.garment-card` `.garment-card__title` |
| 元素 id | `页面-用途` | `#wardrobe-grid` `#outfit-canvas` |
| JS 函数 | 小驼峰 | `renderGarmentGrid()` |
| 常量 | 大写下划线 | `const MAX_SCALE = 3.0` |
| data 属性 | 小写连字符 | `data-garment-id` |

### 4.4 CSS

- **所有颜色、圆角、间距、字号都写在 `variables.css` 的 `:root` 变量里**
- 组件样式放 `components.css`，页面样式放对应页面文件
- 不使用 `!important`，除非覆盖第三方内联样式（本项目没有）
- 单位：尺寸用 `px`，间距用 `px`（保证与设计稿一致），字体大小用 `px`

```css
:root {
  --bg: #ffffff;
  --surface: #fafafa;
  --border: #ebebeb;
  --text: #1a1a1a;
  --text-muted: #8a8a8a;
  --danger: #d94a4a;
  --radius-card: 12px;
  --radius-btn: 8px;
  --space-1: 8px;
  --space-2: 16px;
  --space-3: 24px;
  --font-sans: "Manrope", "Microsoft YaHei", "PingFang SC", sans-serif;
}
```

### 4.5 交互细节

- 所有可点击元素必须有 `:hover` 与 `:active` 反馈
- 拖动元素时加 `.is-dragging`（`cursor: grabbing; box-shadow`）
- 加载中显示骨架屏，不显示空白
- 错误统一用 toast，文案必须是用户能看懂的中文

## 五、错误处理

### 5.1 分层

| 层 | 职责 |
|----|------|
| `services/` | 业务校验失败抛 `ServiceError("中文提示")` |
| `api/` | 捕获异常 → 转换成 `{ok:false, error}`，**不抛出 HTTP 500 页面** |
| 前端 | 统一在 `api.js` 里判断 `ok`，失败时 toast 显示 `error` |

### 5.2 异常类

```python
class ServiceError(Exception):
    """业务异常：消息会直接展示给用户。"""

class NotFoundError(ServiceError):
    """资源不存在。"""
```

### 5.3 用户可见文案示例

| 场景 | 文案 |
|------|------|
| 图片没有透明区域 | 「这张图没有透明背景，请先用 AI 工具抠图后再上传」 |
| 三张图高度差异过大 | 「三张图的比例差异较大，旋转时可能对不齐，建议重新拍摄」 |
| 删除衣服成功 | 「已删除」 |
| 数据库写入失败 | 「保存失败，请重试。如果反复出现，请重启程序」 |

### 5.4 禁止

- 禁止把 Python 异常堆栈直接显示给用户（写到日志里）
- 禁止静默吞掉异常（`except: pass`）

## 六、日志

- 位置：`logs/app.log`（打包后为 exe 同级 `logs/`）
- 格式：`时间 | 级别 | 模块 | 消息`
- 级别：开发用 `DEBUG`，日常 `INFO`，异常 `ERROR` 并带堆栈
- 单个文件超过 5MB 自动轮转，保留最近 3 个
- 启动时记录：版本、Python 版本、数据目录、端口

```python
logger.info("启动完成 port=%s data_dir=%s", port, DATA_DIR)
logger.exception("导入图片失败 garment_id=%s angle=%s", gid, angle)
```

## 七、文件与资源

| 项目 | 规定 |
|------|------|
| 目录名 | 中文界面、英文代码目录（`app/` `web/` `data/`） |
| Python 文件 | `snake_case.py` |
| JS/CSS 文件 | `kebab-case.js` / `kebab-case.css` |
| 图片资源 | `kebab-case.webp`；衣服图片按 id 分目录 |
| 临时文件 | 一律放 `data/tmp/`，启动时清空 |
| 绝对路径 | 只允许出现在 `config.py`，其他文件从 config 取 |

### 7.1 路径工具（config.py）

```python
import sys
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parent.parent


def resource_path(relative: str) -> Path:
    """定位随 exe 打包的资源（web 目录等）。"""
    base = Path(getattr(sys, "_MEIPASS", PROJECT_ROOT))
    return base / relative


def app_dir() -> Path:
    """定位数据目录：开发时在项目根目录，打包后在 exe 同级。"""
    if getattr(sys, "frozen", False):
        return Path(sys.executable).resolve().parent
    return PROJECT_ROOT


DATA_DIR = app_dir() / "data"
LOG_DIR = app_dir() / "logs"
DB_PATH = DATA_DIR / "wardrobe.db"
```

## 八、数据安全规则

1. **删除衣服前二次确认**，文案写明「会同时删除三张图片」
2. **删除时先删数据库记录（事务内），再删图片目录**；图片删除失败只记日志，不阻断
3. **搭配自动保存**，用户不需要点保存按钮
4. **所有用户原始图片保留在 `original/`**，即使处理失败也能重新处理
5. **不在代码里写死任何用户数据路径**
6. 程序退出前关闭数据库连接、停止 HTTP 服务
