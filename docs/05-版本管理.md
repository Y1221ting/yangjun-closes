# 05 - 版本管理

> 个人衣柜 · Git 工作流与提交规范
> 文档版本：v1.0　|　2026-11-18

---

## 一、基本规则

1. **主分支 `main` 始终保持可运行**
2. **每完成一个功能点 → 测试通过 → 提交 → 推送**
3. **不提交运行数据**：`data/`、`logs/`、`衣服生成图/`、`dist/`、`.venv/` 都在 `.gitignore` 中
4. **提交信息用中文说明「做了什么」**，类型前缀用英文

## 三、提交信息规范

格式：

```
<类型>: <一句话说明>

- 具体改动 1
- 具体改动 2

Co-Authored-By: Claude Code <noreply@anthropic.com>
```

### 类型

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: 实现搭配画布拖放` |
| `fix` | 修复 bug | `fix: 修复侧面图未对齐问题` |
| `docs` | 文档 | `docs: 补充图片生成提示词` |
| `test` | 测试 | `test: 补充旋转角度单元测试` |
| `refactor` | 重构，不改行为 | `refactor: 拆分图片处理服务` |
| `chore` | 构建、打包、杂项 | `chore: 更新打包脚本` |

## 四、每个功能的开发步骤

以「阶段 4 搭配画布」为例：

```
1. 从 main 确认最新
   git pull

2. 开发 + 自测
   写代码 → 跑 tests/ → 手动验证

3. 查看改动
   git status
   git diff

4. 只提交相关文件
   git add app/services/outfit_service.py web/js/outfit-editor.js ...

5. 提交
   git commit -m "feat: 实现搭配画布拖放与保存"

6. 推送
   git push

7. 更新开发日志（可单独一次 docs 提交）
```

> 一个功能点一个提交。不要把「做了一半的东西」提交到 main。

## 五、分支策略（单人开发）

默认直接在 `main` 上开发即可。遇到以下情况再开分支：

| 情况 | 做法 |
|------|------|
| 大改架构、可能推翻 | `git switch -c experiment/xxx`，成功后合并，失败直接删 |
| 修紧急问题但手头有半成品 | 先提交半成品，再修 |

合并回 main：

```bash
git switch main
git merge experiment/xxx
git push
```

## 六、版本标签

每个阶段完成后打一个标签，方便回退：

```bash
git tag v0.1.0          # 阶段 0~3：衣柜 + 旋转
git tag v0.2.0          # 阶段 4~5：搭配画布 + 搭配库
git tag v0.3.0          # 配饰收纳区：挂杆 / 纸袋 / 平放
git tag v0.4.0          # 鞋柜 + 纸袋悬停展开
git tag v0.5.0          # 大型嵌入式衣帽柜
git tag v0.6.0          # 秋日手作风 + 欢迎页
git tag v0.7.0          # 搭配页基准模特
git tag v1.0.0          # 阶段 6~8：上身 + 导出 + 打包
git push --tags
```

查看标签：

```bash
git tag
```

回退到某个版本（只查看）：

```bash
git checkout v0.1.0
```

## 七、误操作怎么恢复

| 情况 | 命令 |
|------|------|
| 改错了，想丢弃未提交的修改 | `git restore <文件>` |
| 提交信息写错，还没推送 | `git commit --amend` |
| 想撤销最近一次提交，保留修改 | `git reset --soft HEAD~1` |
| 想看某次提交改了什么 | `git show <提交号>` |
| 看文件历史 | `git log --oneline -- <文件>` |

> 已经推送的提交不要用 `reset --hard` 改写历史，用新的提交去修正。

## 八、不提交的内容

`.gitignore` 已排除：

| 目录 | 原因 |
|------|------|
| `.venv/` | 虚拟环境，每台机器自己建 |
| `data/` | 你的衣服图片和数据库，属于个人数据 |
| `logs/` | 运行日志 |
| `衣服生成图/` | 体积大的个人素材 |
| `build/` `dist/` | 打包产物 |
| `__pycache__/` | Python 缓存 |

> 换电脑时，`data/` 单独用 U 盘或网盘同步，不要放进 Git。
