# 02 - 技术方案

> 个人衣柜 · 技术选型、架构、数据结构与关键算法
> 文档版本：v1.0　|　编写日期：2026-11-18

---

## 一、技术选型

| 层次 | 选型 | 理由 |
|------|------|------|
| 桌面外壳 | **pywebview** | Windows 下调用系统自带的 Edge WebView2，不需要打包浏览器内核，体积小 |
| 本地服务 | **Python 标准库 `http.server`** | 零依赖、可控、能同时提供前端页面和图片，避免 `file://` 的各种限制 |
| 前端 | **原生 HTML + CSS + JavaScript** | 不引入框架和构建工具，改一行就能看到效果，打包不会有 node_modules |
| 数据库 | **SQLite（标准库 `sqlite3`）** | 单文件、免安装、支持事务，30~100 件衣服绰绰有余 |
| 图片处理 | **Pillow** | 裁剪、缩放、转 webp、生成缩略图 |
| 打包 | **PyInstaller** | 生成单个 `.exe` |
| Python 版本 | **3.11** | 机器上已有；默认的 3.8 太旧，禁止使用 |

### 为什么不用这些

| 方案 | 不用的原因 |
|------|-----------|
| Electron | 需要 Node 打包整个 Chromium，成品 150MB+，启动慢 |
| tkinter | 图片网格、透明 PNG 叠加、拖拽画布都很难做 |
| FastAPI / Flask | 需要额外依赖，本项目接口不多，标准库足够 |
| 浏览器 + 本地服务 | 用户明确要「桌面窗口」，不接受先开浏览器 |

```
└────────────────────────┼─────────────────────────────┘
                         │  fetch JSON / 二进制

        ┌────────────────────────────────────┐

        │  · 静态文件：/web  /data           │

        └────────────────┬───────────────────┘
                         │
        ┌────────────────┼───────────────────┐
        ▼                ▼                   ▼
  ┌──────────┐   ┌────────────┐   ┌────────────────┐
  │ services │   │  models    │   │ image_service  │
  │ 业务逻辑 │   │ 数据转换   │   │ 裁剪/缩放/缩略图│
  └────┬─────┘   └─────┬──────┘   └────────┬───────┘
       └───────────────┼────────────────────┘
                       ▼
            ┌─────────────────────┐
            │  db.py  SQLite      │
            │  data/wardrobe.db   │
            │  data/garments/...  │
            └─────────────────────┘
```

**启动顺序**

1. `main.py` 创建 `data/` 目录与数据库（首次运行时建表）
2. 启动 HTTP 服务（绑定 `127.0.0.1` 的随机空闲端口，后台线程）
3. 打开 pywebview 窗口，地址指向 `http://127.0.0.1:<端口>/`
4. 关闭窗口 → 停止服务 → 退出

## 四、数据库设计

### 4.1 建表 SQL

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- 衣服
CREATE TABLE IF NOT EXISTS garments (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    name          TEXT    NOT NULL,
    category      TEXT    NOT NULL,   -- top/outer/bottom/dress/shoes/bag/hat/accessory
    color         TEXT,               -- 预设色名，如 black / white / denim
    seasons       TEXT,               -- JSON 数组：["spring","summer"]
    occasions     TEXT,               -- JSON 数组：场景名称
    brand         TEXT,
    price         REAL,
    purchase_date TEXT,               -- YYYY-MM-DD
    notes         TEXT,
    wear_count    INTEGER NOT NULL DEFAULT 0,
    last_worn     TEXT,               -- YYYY-MM-DD
    created_at    TEXT    NOT NULL,
    updated_at    TEXT,
    deleted_at    TEXT,               -- 软删除时间，NULL 表示正常
    sort_order    INTEGER NOT NULL DEFAULT 0,   -- 同类别的挂杆顺序
    display_style TEXT    NOT NULL DEFAULT 'hang', -- 配饰摆放：hang/bag/flat/drawer
    cabinet_slot  INTEGER               -- 衣帽柜分区内的格位，空表示不进柜
);

-- 角度图（每件衣服最多三张：front / side / back）
CREATE TABLE IF NOT EXISTS garment_images (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    garment_id INTEGER NOT NULL,
    angle      TEXT    NOT NULL,
    path       TEXT    NOT NULL,      -- 相对 data/ 的路径
    width      INTEGER,
    height     INTEGER,
    scale      REAL    NOT NULL DEFAULT 1.0,   -- 单角度大小微调
    offset_x   REAL    NOT NULL DEFAULT 0,     -- 水平偏移（百分比）
    offset_y   REAL    NOT NULL DEFAULT 0,     -- 垂直偏移（百分比）
    FOREIGN KEY (garment_id) REFERENCES garments(id) ON DELETE CASCADE,
    UNIQUE (garment_id, angle)
);

-- 搭配
CREATE TABLE IF NOT EXISTS outfits (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT    NOT NULL,
    scenes     TEXT,                  -- JSON 数组：["daily","daily"]
    notes      TEXT,
    created_at TEXT    NOT NULL,
    updated_at TEXT
);

-- 搭配中的每件衣服：平铺视图和上身视图各一行
CREATE TABLE IF NOT EXISTS outfit_items (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    outfit_id  INTEGER NOT NULL,
    garment_id INTEGER NOT NULL,
    view       TEXT    NOT NULL,      -- flat / worn
    x          REAL    NOT NULL,      -- 归一化中心点 0~1
    y          REAL    NOT NULL,
    scale      REAL    NOT NULL DEFAULT 1.0,
    rotation   REAL    NOT NULL DEFAULT 0,
    z_index    INTEGER NOT NULL DEFAULT 0,
    locked     INTEGER NOT NULL DEFAULT 0,   -- 1 = 用户手动调过，不再自动摆放
    FOREIGN KEY (outfit_id) REFERENCES outfits(id) ON DELETE CASCADE,
    FOREIGN KEY (garment_id) REFERENCES garments(id) ON DELETE CASCADE
);

-- 场景标签
CREATE TABLE IF NOT EXISTS scenes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT    NOT NULL UNIQUE,
    builtin    INTEGER NOT NULL DEFAULT 0,
    sort_order INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_garments_category ON garments(category);
CREATE INDEX IF NOT EXISTS idx_images_garment    ON garment_images(garment_id);
CREATE INDEX IF NOT EXISTS idx_items_outfit_view ON outfit_items(outfit_id, view);
```

### 4.2 初始数据

场景标签预置四条：`日常`、`社交`、`休闲`、`正式`。

### 4.3 约定

- 列表类字段（seasons / occasions / scenes）统一存 **JSON 字符串**，读写时用
  `json.dumps(ensure_ascii=False)` / `json.loads`
- 所有时间用本地时间字符串 `YYYY-MM-DD HH:MM:SS`
- 删除衣服时，`outfit_items` 由外键 `ON DELETE CASCADE` 自动清理；
  数据库连接必须打开 `PRAGMA foreign_keys = ON`
- 坐标统一用 **归一化值（0~1）**，画布逻辑尺寸变化不影响已有搭配
- 配饰的首页摆放方式存 `display_style`：`hang` 挂杆 / `bag` 纸袋 / `flat` 平放 /
  `drawer` 抽屉；非配饰类别保留默认值，不影响原有展示
- 衣帽柜格位存 `cabinet_slot`，按分区各自从 0 开始：
  鞋 `shoes`、包 `bag`、帽子 `hat`、抽屉配饰 `drawer`；新物品补本区第一个空格，
  删除留空，超出基础格位时前端按最大格位增加层数

## 五、图片处理管线

### 5.1 用户提供的输入

三张透明背景 PNG（用户自己用 AI 工具抠好）。程序要求：

- 必须是带透明通道的 PNG
- 最短边 ≥ 200px
- 三张图尽量是同一件衣服的同一角度基准

### 5.2 导入流程

```
读取 PNG → 转 RGBA
   ↓
取 alpha 通道的边界框（去掉四周透明空白）
   ↓
边界框为空？ → 报错「这张图没有透明区域，可能没抠图」
   ↓
以正面图的高度为基准 H
   ↓
侧/背等比缩放，使高度 = H（差异 > 35% 时记录警告，仍可保存）
   ↓
最长边超过 1600px 则等比缩小
   ↓
水平居中、垂直居中（各自独立居中）
   ↓
保存为 WebP（quality=90，保留透明），同时把原始 PNG 备份到 original/
   ↓
生成 thumb.webp（最长边 400px）
```

### 5.3 为什么用 WebP

- 同样画质下体积约为 PNG 的 1/4 ~ 1/5，100 件衣服省下几百 MB
- 支持透明通道
- WebView2（Chromium 内核）原生支持

### 5.4 模特照片

- 用户上传全身照（JPG / PNG 均可，透明背景更佳）
- 等比缩放到画布 1200×1600 内，居中，四周补透明
- 保存为 `data/model/portrait.webp`
- **程序不做人物抠图**：背景不干净时由用户自己处理

## 六、三图旋转实现

### 6.1 数据

每件衣服 3~5 张图：`front`(0°)、`front45`(45°)、`side`(90°)、`back135`(135°)、
`back`(180°)。缺失的角度自动跳过，剩余帧按各自理想角度参与插值；
只有一张图时退化为静态展示。

### 6.2 状态

```
angle ∈ [0, 180]     0 = 正面，90 = 侧面，180 = 背面
```

鼠标水平拖动：`angle += dx * 0.6`，然后钳制到 `[0, 180]`。
双击复位到 0。

### 6.3 显示规则

当前角度落在相邻两帧之间时，就在这两帧之间做交叉淡化与反向旋转；
角度跨过某帧的理想位置时，该帧成为当前帧。帧数越少，单次过渡的跨度越大；
补上 45° / 135° 后，每段跨度从 90° 降到 45°，拖动更连贯。

### 6.4 视觉公式（参数在实现阶段微调）

以每张图的「理想角度」为基准：front=0，front45=45，side=90，back135=135，back=180。

```
偏移 = angle - 该图理想角度
显示角度 = -偏移 * 0.45              // 图自身轻微反向旋转，模拟转过
水平压缩 = cos(min(|偏移|, 90) 的弧度)  // 越接近 90°，图越窄
透明度 = 1 - clamp((|偏移| - 30) / 30, 0, 1)
```

- 两张图同时可见时，透明度交叉，避免硬切
- 容器加 `perspective: 1200px`，图片 `transform-style: preserve-3d`
- 用 `requestAnimationFrame` 播放，拖动结束后 200ms 缓动到最近的 0 / 90 / 180
  （可选：松手吸附，也可不吸附，由实现阶段看效果决定）

### 6.5 单角度微调

AI 生成的多角度图经常比例不一致（例如侧面图偏高，统一高度后显得偏小）。
每张角度图支持独立的：

- `scale`：60% ~ 140%
- `offset_x`：水平偏移 -30% ~ 30%
- `offset_y`：垂直偏移 -30% ~ 30%

微调值存于 `garment_images` 表，旋转时与帧动画叠加应用。
详情页每个角度行展开「微调」面板即可调整，拖动滑块实时预览，松手自动保存。

### 6.6 性能

- 三张图预加载，切换时只改 transform 和 opacity
- 不使用 Canvas 逐帧绘制，避免高分辨率下的卡顿

## 七、搭配画布

### 7.1 画布

- 逻辑尺寸：**1200 × 1600**（3:4 竖版，适合全身搭配）
- 屏幕显示时等比缩放，所有坐标存归一化值
- 背景：纯白（平铺视图）或模特照片（上身视图）

### 7.2 单品显示尺寸

不同类别在画布上的**基准宽度**（占画布宽度比例）：

| 类别 | 基准宽度 | 平铺默认位置 (x, y) |
|------|---------|-------------------|
| 外套 outer | 42% | 0.50, 0.30 |
| 上衣 top | 38% | 0.50, 0.34 |
| 连衣裙 dress | 42% | 0.50, 0.48 |
| 下装 bottom | 34% | 0.50, 0.66 |
| 鞋 shoes | 20% | 0.50, 0.88 |
| 包 bag | 16% | 0.76, 0.56 |
| 配饰 accessory | 12% | 0.50, 0.18 |

新拖入的单品放在该类别默认位置；同类已有单品时向下错开 4%。

### 7.3 交互

| 操作 | 行为 |
|------|------|
| 拖拽 | 移动，实时更新 |
| 滚轮 | 以鼠标为中心缩放 |
| 点击 | 选中，显示边框与控制条 |
| 右键 / 控制条 | 置顶、置底、上移一层、下移一层、删除 |
| Delete | 删除选中 |
| 双击 | 该单品锁定 / 解锁（锁定后不可拖动） |
| 拖出画布 | 删除（带确认） |

### 7.4 实现方式

- 每个单品是一个 `<div class="outfit-item">`，内部 `<img>`
- 位置用 `transform: translate(-50%, -50%) translate(px, px) scale(s) rotate(deg)`
- 事件用 **Pointer Events**（`pointerdown/move/up`），统一鼠标和触控
- 拖动时只在 `requestAnimationFrame` 里改样式，松手才写数据库

### 7.5 保存

- 每次变更后 **800ms 防抖**，PUT 到 `/api/outfits/{id}/items`
- 请求体：`[{garment_id, view, x, y, scale, rotation, z_index, locked}, ...]`
- 保存成功顶部显示「已保存」，2 秒后消失

## 八、上身预览

### 8.1 切换

搭配编辑页顶部有「平铺 / 上身」切换。切到上身时：

1. 画布背景换成模特照片（没有则提示上传）
2. 加载 `view = worn` 的 items
3. 如果 worn 视图为空 → 从 flat 视图的衣物列表按类别自动生成位置（`locked = 0`）

### 8.2 槽位表（归一化，中心点）

| 类别 | x | y | 基础宽度 |
|------|---|---|---------|
| 配饰 accessory | 0.50 | 0.18 | 12% |
| 外套 outer | 0.50 | 0.30 | 36% |
| 上衣 top | 0.50 | 0.33 | 32% |
| 连衣裙 dress | 0.50 | 0.48 | 34% |
| 包 bag | 0.70 | 0.56 | 15% |
| 下装 bottom | 0.50 | 0.62 | 30% |
| 鞋 shoes | 0.50 | 0.93 | 20% |

> 这些数值基于「模特头顶约在 y=0.05、脚底约在 y=0.97」的全身照。
> 用户可通过**整体校准**调整：设置页有「模特头顶 / 脚底位置」两个滑块，
> 保存后所有槽位按比例重新计算。

### 8.3 手动调整

- 用户拖动任一单品后，该 item 的 `locked` 置 1
- 之后再次进入上身视图，`locked = 1` 的不再自动定位
- 提供「重新自动摆放」按钮，把所有 `locked` 清零后重新计算

---

### 8.4 单件遮挡（已实现）

画布中的每件单品支持上下边缘裁切（`clip_top` / `clip_bottom`），用于：

- 衬衫下摆塞进裤子
- 毛衣下摆藏在裙腰后
- 短上衣裁短

数据存于 `outfit_items`，画布、封面预览与导出 PNG 统一应用。
上边缘不得大于下边缘，保存时自动纠正。

### 8.5 未来方案（未实现）

| 方案 | 用途 |
|------|------|
| 橡皮擦遮罩 | 按搭配保存任意形状的遮罩，处理伸出的袖子、领口 |
| 敞开版衣物 | 外套 / 开衫生成敞开状态，露出内搭 |
| 固定模特穿着版 | 每件衣服生成同一模特姿势的透明图层，上身混搭时遮挡关系真实 |

## 九、导出图片

1. 前端创建 1200×1600 的 `<canvas>`
2. 绘制背景（白底或模特照片）
3. 按 `z_index` 排序，用 `drawImage` + transform 依次绘制每件衣服
4. `canvas.toBlob('image/png')`
5. `POST /api/export?name=<搭配名>` 原始二进制上传
6. Python 保存到 `data/exports/<搭配名>_<时间戳>.png`
7. 返回路径，前端提示「已保存」，并调用系统「打开文件夹」

> 同源 HTTP 服务下 canvas 不会污染，`toBlob` 可正常使用。

## 十、接口设计

所有接口返回 JSON，统一结构：

```json
{ "ok": true,  "data": ... }
{ "ok": false, "error": "人类可读的中文错误信息" }
```

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/meta` | 类别、颜色、季节、场景字典 |
| GET | `/api/garments?category=&color=&season=&scene=&q=` | 衣服列表（支持组合筛选） |
| POST | `/api/garments` | 新建衣服（JSON 元信息） |
| GET | `/api/garments/{id}` | 衣服详情（含三张图路径） |

### 11.1 Python 版本

机器上默认 `python` 是 3.8.0（太旧），**必须使用 `py -3.11`**。

```bash
uv venv --python 3.11 .venv
uv pip install -r requirements.txt
```

### 11.2 requirements.txt

```text
pywebview>=5.0
Pillow>=10.0
```

打包时才需要：

```text
pyinstaller>=6.0
```

### 11.3 前端

无任何 npm 依赖。使用**经典 `<script>` 标签 + 全局命名空间 `App`**，
不使用 ES Module（`file://` 和部分 WebView 环境下模块加载会被拦截；
本项目已用本地 HTTP 服务，但仍统一用经典脚本以降低复杂度）。

每个 JS 文件写成：

```js
(function (App) {
  'use strict';
  // ...
  App.wardrobe = { init, render };
})(window.App = window.App || {});
```

## 十二、打包

```bash
pyinstaller --noconfirm --onefile --windowed ^
  --name=个人衣柜 ^
  --icon=web/assets/icon.ico ^
  --add-data "web;web" ^
  --collect-all webview --collect-all pythonnet --collect-all clr_loader ^
  main.py
```

要点：

- `--add-data "web;web"` 把前端打进 exe，运行时用 `sys._MEIPASS` 定位
- 数据目录放在 **exe 同级** 的 `data/`，用户拷走文件夹即可迁移
- `--onefile` 启动约 3~5 秒；若嫌慢，可改 `--onedir`（启动 1~2 秒，但产物是文件夹）
- 首次打包前先用小 Demo 验证 pywebview 能正常打包运行，再写业务功能

## 十三、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 默认 Python 是 3.8 | 装不上新库 | 全项目固定 `py -3.11`，虚拟环境隔离 |
| pywebview 打包失败 | 出不了 exe | **阶段 0 先验证打包链路**，发现问题立刻换方案（Electron / 启动器打开浏览器） |
| 三张图角度不一致 | 旋转时跳动 | 自动按高度对齐；提供单图「水平/垂直微调」滑块 |
| 用户拍的照片没抠干净 | 画面有杂边 | 导入时检测 alpha 边界，给出提示；允许替换单张图 |
| 图片太大 | 启动慢、占空间 | 统一转 WebP，缩略图懒加载 |
| 中文路径 / 打包后资源找不到 | 程序闪退 | 全部用 `pathlib`；资源用 `sys._MEIPASS`；日志记录启动异常 |
| 数据库被意外关闭 | 数据损坏 | WAL 模式 + 每次操作独立连接 + 事务 |
| 模特身高比例不同 | 衣服位置不准 | 设置页提供头顶/脚底校准滑块 |
| 衣服数量到 100 件 | 衣柜页卡顿 | 缩略图 400px + `loading="lazy"` + 分类分页（每页 60） |

## 十四、性能策略

| 项目 | 策略 |
|------|------|
| 图片体积 | 原图备份，展示用 WebP（质量 90），缩略图 400px |
| 衣柜页 | 缩略图懒加载；筛选在数据库层完成，不在前端过滤 |
| 搭配画布 | 只对 transform 做动画；拖动期间不写数据库 |
| 数据库 | 常用字段建索引；连接用完即关；WAL 提升并发读 |
| 启动 | 延迟初始化：先显示窗口骨架，再异步拉数据 |
| 打包体积 | 不引入 numpy/opencv 等大依赖，预计 exe 30~50MB |

## 十五、关键技术决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 前端是否用框架 | 不用 | 页面数量少，框架带来的构建复杂度不值得 |
| 是否内置抠图 | 不内置 | 用户已有 AI 工具；内置模型体积大、CPU 慢 |
| 是否做真 3D | 不做 | 三张照片无法生成真实 3D 模型 |
| 平铺/上身坐标 | 分开存 | 平铺是自由拼贴，上身需要贴合人体，两者布局差异大 |
| AI 调用 | 不在程序内调用 | 用户自己在网页生成后导入，零成本、零密钥 |
